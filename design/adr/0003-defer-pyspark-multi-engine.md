# ADR 0003 — PySpark·멀티엔진 변환 보류

- 상태: 채택 (보류 결정)
- 날짜: 2026-07-09

## 맥락
요구 7: SQL·PySpark 모델 지원, Partition 기반 의존성, 모든 엔진의 모델을 하나의 의존
그래프로 구성. 초기 기획에도 "빈도값 데이터로 Worker 활용" 언급이 있다.
다만 요구 8이 명시하듯 이는 참고한 아이디어이며, 현 워크로드는 5~10분 배치·정형 SQL이다.

## 결정
- 변환 엔진은 **dbt-postgres 단일**로 시작한다. PySpark·파티션 의존성·멀티엔진 그래프는
  도입하지 않는다 (2026-07-09 사용자 확정).
- 재검토 트리거: 빈도값 분석 등 Postgres SQL로 비합리적인 워크로드가 실체화될 때 —
  그 시점에 dbt-spark 어댑터 vs 별도 Worker를 새 ADR로 결정.

## 결과
- (+) 스택·운영 단순. Manager/Model DAG 팩토리도 dbt manifest 단일 그래프만 다루면 됨.
- (−) 대용량·비SQL 워크로드 등장 시 재설계 비용 — manifest 기반 팩토리 구조는 엔진이 늘어도
  그래프 소스만 바뀌므로 확장 여지는 남는다.
