# 01. 개요

## 문제
- 레거시 앱 VIEW_TABLE 불신 → 엔지니어별 Excel 재가공 → **개인 판단이 만든 불규칙한 그림자 데이터 프로덕트**.
- 엔지니어는 담당 영역만 알고, **전체 비즈니스 플로우 문서가 없다** — VOC 패치로만 변형, 합의 사항 방치.
- **이 문제를 인식하고 풀어나갈 전문가가 없다** (요구 문제 4) — 사람에게 기대할 수 없으므로 지식이 시스템에 남아야 한다.
- 결과: 같은 지표가 담당자마다 다른 값, 재현·검증 불가.

## 목적
1. **표준화** — 실무 담당자의 변환 논리를 발굴해 dbt 모델(SQL)로 단일화, brz→slv→gld 계층에 정착 (→ [10](10_NAMING_ORGANIZATION.md)).
2. **가시화** — 비즈니스 정의(용어집)와 계보(리니지)로 현재 데이터 흐름을 본다 (팔란티어 온톨로지 지향).
3. **셀프서비스** — 도메인 지식이 높은 분석가가 SQL·정의서를 직접 추가하면 파이프라인에 자동 반영.
4. **팀 역량** — 위 과정 자체가 PCS기술팀의 업무 능력·데이터 활용능력 향상 수단이며, **전문가 부재(문제 4)에 대한 응답**이다: 암묵지를 glossary·인테이크 기록·계층 계약으로 시스템에 축적하고, 온보딩 가이드([GUIDE.md](../GUIDE.md))와 Agent 협업으로 비전문가의 진입장벽을 낮춰 내부 전문가를 길러낸다.

PCS기술팀 엔지니어(=분석가·도메인 전문가) · 시스템 담당 · 품질 담당.
